**잘한 점**

- **`-l 11`(원래 뇌 코덱, 64MB 블록)이 5개 중 4개에서 가장 작아요.** 위키백과 텍스트·표준 세트·설치 폴더에서는 xz·7z의 최고 압축보다 **12~18% 더 작고** 여러 버전 백업에서도 3~5% 더 작아요.
- **`--max`(빠른 뇌 코덱, 16MB 블록)는 `-l 11`보다 압축·해제가 1.6~2.3배 빨라요.** 파일 하나 꺼내기는 4.8~6.5배 빨라져서 71~115초 걸리던 게 15~20초가 됐어요. 코어가 4개인 맥에서는 차이가 4배쯤이에요(텍스트 48MB 압축 38초 → 9초, 해제 41초 → 10초). 텍스트에서는 여전히 xz보다 한참 작고(위키백과 13.3%, 표준 세트 10.9% 작음), 압축 시간은 모든 데이터에서 xz -9e보다 짧아요(위키백과 53초 vs 150초).
- **작은 파일에서는 뇌 코덱이 더 크게 앞서요.** 예시 글과 코드, 데이터 75KB로 미리 배운 상태(타고난 지식)에서 시작하기 때문이에요. 작은 파일 15개를 합치면 `--max`가 xz -9e보다 19.9%, zip -9보다 26.4% 작고, 파일 하나하나를 봐도 `--max`보다 작은 건 `-l 11`뿐이에요.
- **실행 파일이 모든 레벨에서 1.8~2.5% 작아졌어요.** x86-64 전처리가 호출 주소뿐 아니라 RIP 상대 주소도 바꾸기 때문이에요. 빠른 뇌 코덱이 기계어에 맞는 모델을 골라 쓰게 되면서 이 데이터의 `--max`는 ezpz 0.2.0보다 7.2% 작아졌어요.
- **기본값(`-l 7`)은 tar.zst -19 --long과 크기가 거의 같아요**(커 봐야 2.4%, 표준 세트와 실행 파일에서는 오히려 조금 작음). 압축 시간도 비슷하거나 더 빠르고(표준 세트 78초 vs 113초), 해제는 1.5초 안쪽이에요. 게다가 tar.zst는 못 하는 **파일 하나 꺼내기가 0.1초 이하**예요.
- **`-l 3`은 zip보다 10~33% 작으면서 압축은 5.6~23배 빨라요.** (백업 데이터: zip 41.9초 → ezpz 1.9초)
- **`-l 9`는 xz·7z와 크기가 비슷하면서**(표준 세트와 설치 폴더에서는 셋 중 가장 작음) 해제와 파일 하나 꺼내기가 더 빨라요(표준 세트에서 파일 하나: 1.0초 vs xz 4.3초, 7z 3.5초).
- 해제 결과는 모든 경우에 원본과 바이트 단위로 같았어요.

**부족한 점 (솔직하게)**

- **`--max`는 프로그램 파일과 백업에서 크기를 내줘요.** 설치 폴더와 백업에서는 `-l 11`보다 14~15%, 실행 파일에서는 8% 커요. 백업에서는 7z보다 11.5% 크고, 백업과 실행 파일에서는 `-l 9`가 더 작으면서 해제도 훨씬 빨라요. 손해의 대부분은 16MB 블록에서 나와요. 64MB 블록보다 파일 사이의 비슷한 부분을 덜 활용하거든요. 이런 데이터를 가장 작게 만들려면 `-l 11`을 쓰세요.
- **뇌 코덱은 둘 다 해제가 느려요.** `--max`도 이 서버에서 초당 약 2MB(코어 4개인 맥에서 약 5MB)라 xz보다 수십 배 느려요. 자주 여는 파일보다는 오래 보관할 파일에 맞아요.
- **실행 파일은 아직 `-l 11`이 7z보다 6.0% 커요.** 7z의 x86 전처리기(BCJ2)는 호출 주소를 별도 스트림으로 모으는데 ezpz는 아직 그렇게 하지 않아요. 이 데이터는 큰 Go 프로그램이 대부분이라 x86-64 전처리 효과도 C 프로그램보다 작게 나왔어요(작은 프로그램 145개 표본에서는 6~8%).
- **몇 KB짜리 파일은 기본값이 zip보다 작지 않아요.** ezpz 목록(250바이트쯤, 대부분 해시)이 zstd가 아끼는 만큼을 먹어 버려요.
- **메모리를 많이 써요.** `-l 9`는 압축할 때 zstd 22와 LZMA2 9e를 블록마다 둘 다 시도해서 1.2~1.6GB를 써요. 뇌 코덱은 2스레드 기준 `--max`가 0.4~0.55GB, `-l 11`이 0.4~0.9GB예요.
- **기본값은 tar.zst -19보다 최대 2.4% 커요.** 블록으로 나눠서 병렬 처리와 파일 하나 꺼내기를 얻은 대가예요.
- 모든 수치는 한 번씩 잰 값이고, 느린 가상 서버 기준이에요. 맥 미니(Apple Silicon)에서는 모든 도구가 더 빠를 거예요.

**다음 개선 후보**

- 실행 파일: 호출 주소를 따로 모으는 BCJ2 방식으로 7z와의 남은 차이 줄이기
- 기본 레벨의 작은 파일: 같은 사전 학습 데이터를 zstd 사전으로도 쓰기
- 폴더에서의 `--max`: 병렬 해제는 유지하면서 16MB 블록끼리 배운 내용을 나누기
